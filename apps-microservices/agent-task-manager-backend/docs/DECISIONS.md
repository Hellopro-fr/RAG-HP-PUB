# Decisions

Format: date — decision — reason. Deviations from the build spec are marked **DEVIATION**.

- 2026-11-05 — Product name "Agent Task Board"; services `agent-task-manager-backend` and `agent-task-manager-frontend` (the request said `agent-taskmanager-frontend`; unified for consistency). — Naming consistency inside `apps-microservices/`.
- 2026-11-05 — UI copy in French, design system shadcn/ui + Tailwind. — User choice.
- 2026-11-05 — Deploy target undecided; phase 1 ships `docker compose up` only, tested on a VM. — User choice. If Cloud Run is chosen later: CPU always allocated, min-instances ≥ 1, long request timeout (sweeper, PgListener, SSE are background/long-lived).
- 2026-11-05 — **DEVIATION** (§2 layout): the spec's single repo is split into two monorepo services. `migrations/`, `deploy/`, `scripts/`, `docs/` and the full-stack `docker-compose.yml` live in the backend service; `web/` becomes `agent-task-manager-frontend`. — User request (two services).
- 2026-11-05 — Backend follows a layered architecture with a pure domain leaf: `api → service → {core, repository, realtime}`, `core` depends on nothing. Repositories take `&mut PgConnection`; the service layer owns the transaction. — Classic N-Tier (business calls data, repositories own connections) would break §4's single transaction per command and §2's "core has no IO".
- 2026-11-05 — OpenAPI contract crosses the service boundary as a committed `openapi.json` (backend) and a committed generated `schema.d.ts` (frontend), with a drift check. — Docker build contexts are per service.
- 2026-11-05 — **DEVIATION** (§2 MCP auth): the existing `mcp-gateway-service` terminates the client bearer and sends static per-backend headers, so it cannot "forward" a bearer. It is extended (opt-in per backend) to inject an agent identity header plus a shared secret; the task board trusts that header only with the secret. Direct bearer auth remains. — User choice "extend gateway"; per-actor identity is required by fencing, AC-2.5, `require_different_model`, rate limits.
- 2026-11-05 — **DEVIATION** (§3 `actors`): added `password_hash` (humans, argon2id), `gateway_subject` (gateway identity mapping) and a `sessions` table. — Needed by §8 login and the gateway decision; the spec's table lists only key columns.
- 2026-11-05 — **DEVIATION** (§3 `leases.token`): stored as `token_hash` (SHA-256); `lease.claimed` payloads carry the hash, never the raw token. Writes are validated on (actor_id, token). — The event log is readable by every viewer via SSE and `/events`; a raw token there would let any viewer write as the holder. Replay still rebuilds `leases` exactly.
- 2026-11-05 — Idempotency response is written inside the command's transaction. — A post-commit write would let a crash cause a double apply (AC-1.6).
- 2026-11-05 — Global SSE stream `GET /api/stream?topics=questions,reviews` for cross-project inboxes, without Last-Event-ID resume (client refetches its inbox on reconnect). — User choice; per-project seqs cannot form one global cursor.
- 2026-11-05 — rmcp Streamable HTTP in stateless mode (`NeverSessionManager`). — All state is in Postgres; avoids sticky sessions behind the gateway or with replicas.
- 2026-11-05 — Single-origin ingress in compose is Caddy (`flush_interval -1`, no compression on SSE). — §2 requires an ingress that does not buffer SSE; `api-gateway-go` has no SSE flushing handling.
- 2026-11-05 — Two Postgres roles: `atb_owner` (migrations, `DATABASE_OWNER_URL`) and `atb_app` (runtime, `DATABASE_URL`, no UPDATE/DELETE on `events`). — §3 append-only + §12 least privilege.
- 2026-11-05 — Phase 1 wires `submit_for_test` only for projects with `test_gate = none`; spec approval exists as a minimal human REST endpoint, no editor UI. — Verifier and review flow are phase 2, but tasks need an approved pinned spec to reach `ready` and the demo needs a terminal path. The core decider still implements and unit-tests every §4 row.
- 2026-11-05 — Rate limiting is in-process per replica. — Phase 1 is single-instance; revisit with the Redis notifier (phase 3).
- 2026-11-05 — Enums are `text + CHECK` (the spec allows either). — Simpler with sqlx compile-time macros; same guarantees.
- 2026-11-05 — **DEVIATION** (§4 core API): the lease and the open attempt live in `TaskSnapshot`, not in `Ctx`. — `apply()` must update them for the property test to check invariants on full states; `Ctx` keeps the time, caller, workflow, blockers, approved version, ACs and edges.
- 2026-11-05 — The commit of a submission made without a test gate is carried by `task.state_changed.submission`. — §3 has no event for "submitted without a test run", and replay must rebuild `attempts.commit_sha`.
- 2026-11-05 — The first response of an idempotent command, raw `lease_token` included, is stored in `idempotency_keys` for at most 24 h. — AC-1.6 requires replaying the first response (a retried `claim` must get the same token). This is the only place a raw secret is at rest; it is purged by the sweeper.
- 2026-11-05 — The board snapshot is read in one REPEATABLE READ transaction and returns `seq`; the board stream starts `after=seq`. — No event can fall between the snapshot and the stream.
- 2026-11-05 — The rebuild check (AC-1.8) replays into TEMP tables with the projection names on a fresh connection (`pg_temp` shadows `public`), with the same projector code; nothing is committed. — One projector, no duplicated SQL; a pooled connection could hold statements bound to the live tables.
- 2026-11-05 — MCP tools return failures as tool results (`isError`, code, message, `how_to_fix`) rather than JSON-RPC errors. — §7: errors must tell the agent what to do next; LLM clients show tool results to the model.
- 2026-11-05 — Extra MCP tool `link_tasks`, extra REST `GET /api/projects/{id}/ready`, `POST /api/projects/{id}/claim`, `GET /api/projects/{id}/rebuild-check`. — Humans and scripts need the same claim/list as agents; AC-1.5 needs a way for agents to add `blocks` links after creation.
- 2026-11-05 — **DEVIATION** (plan §1.3): gateway identity forwarding is opted in with the existing per-backend server tag `agent-identity` instead of a new `forward_agent_identity` column. — Same opt-in granularity, no MySQL migration, no admin API or Vue change; tags already drive Zoho routing the same way. The OAuth2 client id is now put in the request context (`scopetoken.ClientIDContextKey`); scope tokens (`mcp_…`) carry no client id, only OAuth2 tokens do.
- 2026-11-05 — Frontend: TypeScript pinned to 5.9.3. — openapi-typescript 7.13 declares `typescript@^5`.
- 2026-11-05 — Frontend: `/agents` polls every 5 s. — Heartbeats are not events (§3), so lease timing cannot arrive over SSE.
- 2026-11-05 — Frontend: drag-and-drop supports only cancellation in phase 1. — It is the only human-initiated transition without a lease; other moves are refused with a message (server still decides).
- 2026-11-05 — Spec gap recorded, to resolve before phase 2: §4 has no rows for `test_gate = human` (testing → in_review on a human check pass, and the fail path). Phase 1 does not use it.
